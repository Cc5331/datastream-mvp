## 1. 拍前准备（10 分钟，逐项打勾）

### 1.1 服务（必须全绿，缺一个就改脚本）

| 步骤 | 命令 / 操作 | 成功判据 |
|---|---|---|
| 1 | 双击根目录 `start-all.bat`（幂等，已在跑的服务会自动跳过） | 结尾汇总 5 行全 OK：Kafka 29092 / Flink 18081 / SQL Gateway 18083 / Backend 18080 / Frontend 3000 |

> ⚠️ **Flink 一定要起**：集群没起时提交的作业会**停在 SUBMITTED**（不会像旧版本那样假装 COMPLETED），录像里会很难看。
> ⚠️ 手工起后端时必须让端口对齐：`FLINK_CLUSTER_PORT=18081`、`FLINK_SQL_GATEWAY_PORT=18083`。

### 1.2 演示素材

- `test-resources/data/sales.csv`（销售数据，中文列名）——主链路用
- `test-resources/data/sample_data.xlsx`（Excel 输入用）
- `test-resources/data/large/sales_150k.csv`（15 万行，性能段可选展示文件大小）
- Kafka 主题 `kafka_sales_flow`（有历史数据才能演示 Kafka 可视化；没有就跳过 3.8 段）
- **Kafka 必须真的在跑**：Kafka 未启动时「Kafka 可视化」页会直接报 500（提示 `无法连接 Kafka（localhost:29092）`），那一段就废了——录制前先在该页点一次「刷新」，确认能列出 topic 再开录
- AI 段：确认 `.env` 里有 `DEEPSEEK_API_KEY` 且网络可达。**智能诊断**有本地规则引擎兜底（Key 挂了也能演，见 3.10）；但 **NL2Pipeline（第 11 段）没有本地兜底**，Key 不可用就整段改成诊断演示

### 1.3 窗口与录制

- 布局：主窗口浏览器 2/3 屏宽（前端），副窗口 1/3（Flink UI 或终端日志）
- 关闭微信/邮件/系统通知；隐藏书签栏；关闭无关标签页
- 建议**画面与配音分开录**：先照 §3 操作清单点一遍（画面），再照 §2 口播稿配音，最后对齐时间轴；一次成片也行，但语速要稳

### 1.4 账号与权限演示准备（**最容易翻车的一段，务必先读**）

平台按**创建人隔离**作业：非管理员登录后，作业列表只返回自己创建的作业。这直接决定「权限演示」镜头怎么拍：

| 方案 | 做法 | 画面效果 |
|---|---|---|
| ✅ 推荐 | 主流程全程用 `admin` 录制；权限镜头另用 `operator` 账号，并**提前用「模板中心 / 示例作业」一键建 1~2 个属于 operator 的作业** | 列表有内容，能同时拍到「正常使用」+「看不到别人的作业」 |
| ⚪ 备选 | 只用 `viewer` 登录，口播讲「按创建人隔离 + 只读」 | 作业列表是**空的**（viewer 不能建作业），别当成 bug，要在配音里说明这是隔离设计 |
| ❌ 不要 | 用 `operator` 去打开/复制 `admin` 的作业 | 打开会被 403 拒绝；**复制作业会继承原 owner**，复制出来的仍是 admin 的，operator 照样看不到 |

其他录制注意：

- **重复点「运行」会弹 409**「作业正在运行中（当前状态 RUNNING），请等待结束或先取消」——这是防重复提交保护（同一作业并发提交已加锁）。等状态变 RUNNING 再操作，别连点。
- **「登出」会让该账号所有端下线**：服务端递增令牌版本，旧 token 立即失效。多标签页录制时，一个标签登出后另一个会跳回登录页，属预期行为，别慌。
- **VIEWER 看不到「Kafka 可视化」入口与画布「预览数据」按钮**（后端同样返回 403）。权限镜头可以顺带展示这一点；但也别打算用 VIEWER 演示 Kafka。
- 账号准备：`admin` 密码见 `.env`；需要 `operator` / `viewer` 时，用管理员在「用户管理」里建一个已知密码的账号（自助注册出来的账号固定是 VIEWER）。

## 3. 关键演示操作清单（照点即可）

1. **登录**：http://localhost:3000 → `admin` / 你在 `.env` 配置的管理员密码
2. **建流**：画布 → 左侧拖 `CSV 输入`、`字段过滤`、`MySQL 输出` → 依次连线 → 逐个点节点填参数
   - CSV 输入：路径 `D:\code\比赛\2026省服务外包\test-resources\data\sales.csv`
   - MySQL 输出：库表按你环境填（默认库 `flink_demo`，自动建表）
   - 右侧「📊 预览数据」确认字段
3. **运行**：保存 → 点运行 → 弹窗看日志 → 切 http://localhost:18081 看作业
4. **产物**：`output/` 下查看输出文件；MySQL 里 `SHOW TABLES;` 看自动建的表
5. **调度**：作业行「⋮ 更多 → 调度」→ 输入「每天凌晨 2 点」→ 看自动生成的 6 段 cron
6. **依赖**：作业行「⋮ 更多 → 依赖」→ 勾选上游 → 保存 → 顶栏「工作流」看依赖图
7. **监控**：顶栏「监控」→ 看统计卡与趋势图；顶栏「Kafka 可视化」→ 选 `kafka_sales_flow` → 开始接收
8. **告警**：新建一个 CSV 输入指向不存在文件 → 运行 → 顶栏「告警中心」看告警 → 点「🤖 诊断」
9. **AI**：顶栏「AI 助手」→ 输入自然语言需求 → 生成 → 打开画布编辑 → 提交前会要求确认草稿
10. **权限（按 §1.4 的方案来，别直接切 viewer）**：
    - 推荐：用提前建好作业的 `operator` 账号登录 → 列表只有自己的作业 → 尝试打开 admin 的作业会被 403 → 展示「按创建人隔离」

    - 权限镜头别忘了一句口播：**登出会让该账号所有端下线**（服务端吊销令牌）

> 界面按钮文案以实际版本为准（本文档按当前版本写；若个别入口名称不同，按功能找即可）。
> 录制中途误登出：重新登录即可；**同一账号在其它标签页会被踢回登录页**，这是令牌吊销的预期表现。
> 重复点「运行」会返回 409（同一作业不允许并发提交），口播一句即可，不用重录。

## 4. 性能测试方案及结果（第 13 段讲稿）

**方案（口播）**：
> 「性能测试跑的是**真实链路**，不是单元基准：`test-resources/benchmark.py` 通过后端 REST 创建作业、提交到真实 Flink 集群，用 `completedAt − submittedAt` 计算端到端耗时，换算出吞吐，同时用 psutil 采集 CPU 与内存，最后产出 `test-results/benchmark_report.md`。测试矩阵是 **10 万行 / 100 万行 × 并行度 1 / 2 / 4**，CSV 透传。另外还有 `acceptance_200k.py` 做 20 万条的全链路验收，检查数据覆盖度、完整性和耗时。」

**结果（画面上放大表格）**：测试机 32 vCPU / 16 GB，2026-08-05 实测（CSV 透传）

| 数据量 | 并行度 1 | 并行度 2 | 并行度 4 |
|---|---|---|---|
| 100,000 行 | 11,628 行/s | 18,774 行/s | **49,032 行/s** |
| 1,000,000 行 | 76,139 行/s | 112,015 行/s | **217,795 行/s** |

**结论（口播）**：
> 「可以看到两个规律：一是数据量越大吞吐越高，因为小作业的固定开销占比大；二是并行度从 1 提到 4，吞吐接近线性提升，说明**翻译层生成的 SQL 和 sink 配置没有成为瓶颈**。百万行数据在并行度 4 下约 4.6 秒完成，完全满足赛事对大数据量处理的要求。此外我们还准备了 15 万行的四格式大数据集——CSV、Excel、JSON、XML——用于演示和压力验证。」

> 若现场不便跑基准脚本：直接展示 `test-results/benchmark_report.md` 与上面这张表即可，不要临场跑 100 万行（耗时且受机器状态影响）。

## 5. 应急降级方案（现场翻车预案）

| 故障 | 现场处理 |
|---|---|
| Flink 没起来 | **不要提交作业**（会停在 SUBMITTED）。改为展示已完成的作业历史 + 监控页历史卡片 + 血缘图 |
| 后端没起来 | 前端会退化为内置控件副本（31 个控件仍可用），可演示画布编排与导出 JSON |
| Kafka 未启动 | 「Kafka 可视化」页会报 500（`无法连接 Kafka（localhost:29092）`）→ 立即跳过该段，用 CSV/MySQL 链路替代，别把报错录进去 |
| AI Key 未配置 / 调用失败 | 智能诊断改演**本地规则引擎**路径（制造一个失败作业，命中即返回根因）；NL2Pipeline 无本地兜底，直接跳过第 11 段或改用诊断代讲 |
| 权限镜头看到空列表 | 用 `viewer` 时属预期（按创建人隔离）。改讲隔离设计，或临场换成 `operator`（前提是它有自己的作业） |
| 误点两次「运行」弹出 409 | 这是防重复提交保护，口播「同一作业不允许重复提交」即可，不必重录；等状态变 RUNNING 再继续 |
| 误登出导致其它标签页被踢 | 令牌吊销的预期行为：重新登录即可，该镜头不必重录 |
| MySQL 不可用 | 输出改为 CSV/Excel，效果同样直观 |
| 演示中断需重录 | 每段独立成篇，可分段录制再拼接；每段开头保留 2 秒静止画面便于剪辑 |
